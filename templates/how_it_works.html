How SecureVault Works

Learn how end-to-end AES-256-GCM encryption, Scrypt key derivation, and SHA-256 integrity verification keep your files private.

1

Select & Validate File

Choose any PDF, DOCX, TXT, ZIP, PNG, JPG, MP4, CSV, or PPTX file up to 50 MB. SecureVault inspects raw magic header bytes to verify authentic file signatures.

2

AES-256-GCM Authenticated Encryption

A unique 16-byte random salt and 12-byte nonce/IV are generated. Key derivation converts your protection password into a 256-bit symmetric key, encrypting the payload with GCM authentication tags.

3

SHA-256 Checksum Storage

Before raw data is discarded, a SHA-256 cryptographic digest is stored in the database. This guarantees zero silent disk corruption or unauthorized payload modifications.

4

Secure Share Token Generation

Generate cryptographically random share URLs (`/share/`). Set optional share passcodes, download limits, and automatic link expiration timers. Passwords are never placed in URLs.

5

Verified Decryption & Download

Recipient inputs the protection password. GCM tag is verified, the file is decrypted, and post-decryption SHA-256 is matched before downloading the original file.

Technical Security Architecture

🔐 Zero-Trust Storage

Encryption keys are derived ephemerally on demand. Plaintext payload keys are never written to disk or logs.

🛡️ OWASP Compliant

Full protections against SQLi, XSS, CSRF, IDOR, MIME spoofing, path traversal, and login brute-force.

📜 Security Audit Logs

Every upload, encryption, decryption, share access, and failed login attempt is recorded with client IP and user-agent.
